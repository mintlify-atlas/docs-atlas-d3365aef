The frontend and mobile development plugins cover the full spectrum of modern client-side work — from React 19 server components and Next.js 15 App Router patterns, to cross-platform React Native and Flutter apps, native iOS with Swift/SwiftUI, and accessible UI design systems. Each agent is assigned a model tier that balances cost against the complexity of the task.

## Scaffold a component

The `component-scaffold` command generates a production-ready React or React Native component including TypeScript types, styles, tests, and Storybook stories:

```bash
/frontend-mobile-development:component-scaffold "UserProfile component with hooks"
/frontend-mobile-development:component-scaffold "DataTable with sorting, filtering, and pagination"
/frontend-mobile-development:component-scaffold "PaymentForm with Stripe Elements -- platform native"
```

Each scaffold produces:

- The component file with proper TypeScript interfaces
- CSS Modules, styled-components, or Tailwind classes (detected from your project)
- A test file with `@testing-library/react` covering render, interaction, and accessibility
- Storybook stories for the default and interactive states
- An index barrel file for clean imports

## Frontend skills

The `frontend-mobile-development` plugin activates these skills based on context:

| Skill | Description |
|---|---|
| `react-state-management` | Zustand, Jotai, and TanStack Query patterns |
| `nextjs-app-router-patterns` | Next.js 14+ App Router, RSC, streaming, and Server Actions |
| `tailwind-design-system` | Design systems with Tailwind CSS, component libraries, and tokens |
| `react-native-architecture` | React Native navigation, native modules, and offline sync |

## Accessibility compliance

Install the `accessibility-compliance` plugin to run WCAG 2.2 audits and screen reader testing alongside your frontend work:

```bash
/plugin install accessibility-compliance
/accessibility-compliance:accessibility-audit
```

The `ui-visual-validator` agent in this plugin performs visual regression testing and verifies that generated components meet accessibility requirements. Skills activated include `wcag-audit-patterns` and `screen-reader-testing` (NVDA, JAWS, and VoiceOver).

## Pull request enhancement

The `comprehensive-review` plugin's `pr-enhance` command runs a multi-perspective review — architecture, security, and performance — over your frontend changes before they merge:

```bash
/plugin install comprehensive-review
/comprehensive-review:pr-enhance
```

The `architect-reviewer` (Opus), `code-reviewer` (Opus), and `security-auditor` (Opus) agents run in parallel, producing a consolidated review with severity-ranked findings.

<Tip>
  The `frontend-developer` and `mobile-developer` agents use the `inherit` model tier, meaning they run on whichever model you start your Claude Code session with (`claude --model sonnet` or `claude --model opus`). This lets you control cost for high-volume component work while keeping Opus available for architecture decisions.
</Tip>

## Multi-platform orchestration

For apps that need to ship on web, iOS, Android, and desktop simultaneously, the `multi-platform-apps` plugin provides a coordinated development command:

```bash
/plugin install multi-platform-apps
/multi-platform-apps:multi-platform "Push notification system with rich media"
```

This coordinates `frontend-developer`, `mobile-developer`, `ios-developer`, `flutter-expert`, and `ui-ux-designer` to produce consistent implementations across all target platforms.
